# Build a golden set Laya cannot game

A trustworthy 500-example golden set for the five-class typer is less a matter of size than of independence: it must come from generators, template groups and label checkers that share nothing with training, it must be split into a gated "core" slice and separately reported hard slices, and the promotion gate must switch from point thresholds to paired statistical tests, because 500 rows measure each class's recall only to about ±0.06. The biggest threat is not random noise but generator leakage: if golden-v2 is made the way training data is made, it will measure how well Laya learned that generator's style, and neither the exact-hash nor the `template_group` exclusion in the label store will notice. The second threat is label error: published test sets carry at least 3.3% wrong labels on average, and five bad items in a 100-item class is a 0.05 recall swing, exactly the size of the gate. The third is the gate itself: today any single-item accuracy drop blocks a promotion, and a perfectly calibrated model still shows binned ECE of about 0.026 at n = 500, so the ECE +0.02 rule mostly measures estimator noise. The practical answer is a 360-row core (70 to 85 per class, generated by two model families that are neither the training generator nor the fallback model, spread over at least 20 template groups per class), plus 64 rule-governed boundary documents, 40 contrast edits and 36 noise variants, all double-labelled under a frozen written guideline and checked by a four-layer contamination report. The specification at the end gives counts, schema, pipeline and the gate changes.

## Five hundred rows measure recall to about ±0.06, so every comparison must be paired

A golden set has two jobs: estimate how good a model is, and decide whether a candidate beats the incumbent. At the planned size it does the second far better than the first. With 100 examples per class, the Wilson 95% interval on a recall near 0.90 is about ±0.06, and near 0.95 about ±0.045; reaching ±0.05 at a recall of 0.80 needs roughly 250 examples per class ([Wilson 1927](https://doi.org/10.1080/01621459.1927.10502953)). The Wald interval should never be used: it collapses to zero width when a class scores 100%, which will happen for `acord`, and has erratic coverage near 0 and 1 ([Brown, Cai & DasGupta 2001](https://doi.org/10.1214/ss/1009213286)). When a class shows zero misses, the "rule of three" gives a one-sided 95% upper bound on the miss rate of about 3/n, so 0.03 at n = 100 ([Hanley & Lippman-Hand 1983](https://doi.org/10.1001/jama.1983.03330370053031)). The research notes worked these numbers from the cited formulas; at the 70-row class sizes proposed below, a 0.90 recall carries a ±0.07 interval.

The paired view is where 500 rows earn their keep. **Dietterich found McNemar's test the only test with acceptable Type I error when each model can be run only once**, which is precisely a fixed candidate checkpoint against a fixed incumbent on a fixed golden set; unpaired two-proportion tests "should not be used" ([Dietterich 1998](https://mlanthology.org/neco/1998/dietterich1998neco-approximate/)). Among McNemar variants, the **mid-p version never exceeded the nominal level in 9,595 scenarios**, while the exact conditional and continuity-corrected versions were too conservative ([Fagerland et al. 2013](https://pubmed.ncbi.nlm.nih.gov/23848987/)). What a paired test can detect depends on the discordance rate, the share of items where exactly one model is right, not on overall accuracy. Using the standard McNemar power formula, the notes find that at N = 500 and 5 to 10% discordance the minimum detectable accuracy difference is about 0.03 to 0.04, against about 0.05 for an unpaired test; for a single class of 100 it is about 0.04 to 0.10. Card et al. found many NLP comparisons underpowered for exactly this reason and recommend running a power analysis before trusting an eval set ([Card et al. 2020](https://arxiv.org/abs/2010.06595)). For any metric without a closed-form test (macro-F1, Brier, ECE), a paired bootstrap that resamples item indices, not each model separately, keeps the pairing ([Efron & Tibshirani 1993](https://doi.org/10.1201/9780429246593)).

These numbers expose the current `PromotionPolicy` in `src/doctype/services/evaluation.py`. Its accuracy rule blocks on any drop at all, which at 500 rows means a single item; its recall rule uses a point threshold of 0.05, which a Monte Carlo in the notes shows trips about 2.8% of the time per class with no true change at 100 items and 8% discordance, compounding to about 13% false blocks across five classes. A false block costs less than a false promotion, so some excess blocking is acceptable on purpose, but it should be a chosen rate, not an accident.

### Build stratified, then reweight to the production prior

Recall is conditional on the true class, so it does not care about the class mix; accuracy, precision and ECE do. The sound design is to stratify the golden set for per-class precision and then report headline accuracy and precision reweighted to the production prior, using the row-normalised confusion matrix and stratified-sampling formulas ([Cochran 1977](https://www.wiley.com/en-us/Sampling+Techniques%2C+3rd+Edition-p-9780471162407); [Saerens et al. 2002](https://doi.org/10.1162/089976602753284446)). In an illustrative calculation with a broker-email-heavy prior, a balanced 100-per-class set widened the prior-weighted accuracy interval only from ±0.019 to ±0.022 while giving `acord` 100 rows instead of 40. The prior should be estimated from routed volume in the decision log, versioned, and stored with each report. Google's guidance to evaluate on data from after the training window and on a small labelled random sample of live traffic points the same way ([Google, Rules of ML](https://developers.google.com/machine-learning/guides/rules-of-ml)). Note one constraint the repo already imposes: invariant 5 reserves the random audit sample for fitting temperature and threshold, so it cannot double as the prior-matched evaluation sample.

### Binned ECE at n = 500 cannot police a 0.02 margin

The ECE gate deserves the bluntest verdict. **Roelofs et al. report that detecting 2% miscalibration needs over 10,000 samples, and that below 500 samples only miscalibration above about 10% is reliably detected**; binned ECE is biased, and the bias is worst for perfectly calibrated models ([Roelofs et al. 2022](https://arxiv.org/abs/2012.08668)). The notes' own simulation found a perfectly calibrated model showing ECE of about 0.026 at n = 500 with 15 equal-width bins, and the difference in ECE between two identically calibrated models had a standard deviation of about 0.009, so a true +0.02 change would be observed anywhere from roughly 0.00 to 0.04. Binned estimators underestimate true calibration error in the limit, and a debiased estimator needs far fewer samples ([Kumar et al. 2019](https://arxiv.org/abs/1909.10155)); top-label ECE also ignores class conditioning and is dominated by one or two bins on sharp models ([Nixon et al. 2019](https://arxiv.org/html/1904.01685)). The evaluation service currently uses 10 equal-width bins. The replacement is a strictly proper scoring rule, Brier or log loss, which needs no binning and can be paired-bootstrapped per item ([Gneiting & Raftery 2007](https://doi.org/10.1198/016214506000001437)), with debiased or sweep ECE reported alongside, the estimator frozen into the golden version, and reliability diagrams drawn with consistency bands ([Bröcker & Smith 2007](https://doi.org/10.1175/WAF993.1)). Classwise calibration on 70 to 100 rows per class is description, never a gate.

The same logic applies to the confidence threshold. Coverage and selective risk should each carry a Wilson interval, with the effective sample being N times coverage; 8 errors among 400 auto-routed items gives a risk of 0.020 with an interval of 0.010 to 0.039. Candidate and incumbent should be compared at matched coverage, not at the same raw threshold, and the golden set should only report the risk at a threshold chosen elsewhere, since choosing among thresholds on it would turn it into a tuning set ([Geifman et al. 2019](https://arxiv.org/html/1805.08206v4); [Geifman & El-Yaniv 2017](https://arxiv.org/abs/1705.08500)).

### Freeze the exam, ration the queries, refresh by version

Reusing a holdout adaptively "can easily lead to overfitting to the holdout set itself" ([Dwork et al. 2015](https://arxiv.org/abs/1506.02629)), and leaderboard-style repeated evaluation overfits unless scores are released only on meaningful improvement ([Blum & Hardt 2015](https://arxiv.org/abs/1502.04585)). Recht et al.'s fresh CIFAR-10 and ImageNet test sets dropped accuracy by 3 to 15 and 11 to 14 points while preserving rankings, which they attribute to slightly harder data rather than reuse ([Recht et al. 2019](https://arxiv.org/abs/1902.10811)); the lesson for this project is to refresh golden data periodically from a new tranche, not only to guard against peeking. Golden-v2 should therefore be an immutable, content-hashed artefact with a datasheet ([Gebru et al.](https://arxiv.org/abs/1803.09010)), shipped with the hash of the metric code and its configuration, corrected only by issuing v2.1 with an errata entry and re-scoring the incumbent, and queried through a log that records who scored which model. No source prescribes a refresh cadence; a quarterly tranche, or one triggered by a measurable shift in the decision-log class prior, is a reasonable default.

## The generator, not the template, is the leak to fear

Leakage is the evaluation rewarding memory of something seen in training. It is endemic: Kapoor and Narayanan found leakage errors across 17 fields affecting 329 papers ([Kapoor & Narayanan 2022](https://arxiv.org/abs/2207.07048)), a count their companion site later raised to 648 papers ([Princeton reproducibility site](https://reproducible.cs.princeton.edu/)). The closest quantitative guide for template-driven text is Elangovan et al.'s AIMed result: moving from random folds to folds split by source document cut mean train/test trigram similarity from 73.15 to 20.77 and **dropped F1 by about 13 points for every model, BioBERT from 77.9 to 64.4** ([Elangovan et al. 2021](https://aclanthology.org/2021.eacl-main.113.pdf)). The same paper summarises Min (2020): keeping each paraphrase template in one split made models perform significantly worse, which is the published analogue of this repo's `template_group` exclusion.

That exclusion is the right instinct with the wrong keys. Broker-level groups such as `aon-sov` and `marsh-sov` in the current data miss three ways near-duplicates cross the line. ACORD forms are industry standard, so two brokers' ACORD 125 pages are near-identical; the `acord` group key should be form number plus edition. A carrier's loss-run export looks the same whichever broker forwards it, so the `loss_run` key should be the carrier or loss-run system. SOVs cluster by spreadsheet header signature as much as by broker. scikit-learn's guidance is that when the generative process yields dependent groups, every validation sample must come from groups absent from training ([scikit-learn cross-validation guide](https://scikit-learn.org/stable/modules/cross_validation.html)). The robust fix is to build a graph whose edges are exact-hash matches, shared declared keys and near-duplicate similarity, take connected components, and exclude whole components; this extends invariant 3 from "hash and template group" to "hash, composite group and near-duplicate component".

Generator leakage sits outside all of those keys. If golden and training rows share an LLM, a prompt family, slot-value lists (insured names, carriers, addresses) and rendering code, the shared factor is the generator itself. There is no published measurement of how much accuracy inflates on a same-generator test set, but the indirect evidence is strong. Li et al. found models trained on GPT-3.5 data lost an average 27.4 macro-F1 on the most subjective tasks when tested on real data, a gap a same-generator test would hide ([Li et al. 2023](https://arxiv.org/pdf/2310.07849v2)); RoSE assumes synthetic data carries its generator's signature and evaluates across generators for that reason ([RoSE 2025](https://arxiv.org/pdf/2510.06143)); and Maheshwari et al. found smaller models scoring higher on data they had generated themselves ([Maheshwari et al. 2024](https://arxiv.org/abs/2409.11968)). The defences are structural: golden generators, prompts, lexicons and slot lists live apart from `scripts/generate_production.py`; generator identity enters the group key; rare slot values shared between golden and training count as a leak even when text similarity is low; and a cross-generator comparison quantifies the effect directly.

### Short texts break web-scale deduplication defaults

The published near-duplicate settings were tuned for long web documents. Lee et al. used word 5-gram MinHash with Jaccard and edit similarity above 0.8 ([Lee et al. 2022](https://ar5iv.labs.arxiv.org/html/2107.06499)); GPT-3 removed any example sharing a 13-gram with training ([GPT-3 supplemental](https://proceedings.nips.cc/paper_files/paper/2020/file/1457c0d6bfcb4967418bfb8ac142f64a-Supplemental.pdf)); GPT-4 sampled three 50-character substrings per example ([GPT-4 technical report](https://arxiv.org/pdf/2303.08774)). On the 10 to 60 word documents in the current stand-in data, a single substituted insured name destroys most word 5-grams, so templated rows with different slots look unrelated, and a 13-gram check degenerates into exact matching. Character 5-grams on normalised text (lower-cased, digits mapped to 0, emails and amounts masked) degrade gracefully, and at this scale brute force is cheap: 500 golden rows against 100,000 training rows is 50 million comparisons, trivial as a sparse TF-IDF product, which removes LSH approximation error entirely ([datasketch LSH docs](https://ekzhu.com/datasketch/lsh.html)). Paraphrase and translation slip past n-gram checks ([contamination study](https://arxiv.org/pdf/2311.04850v1)), so a sentence-embedding nearest-neighbour check is the semantic net, but its threshold must be calibrated on this project's own same-template versus independent same-class pairs, because no validated cosine cut-off exists and a low one would exclude most of `broker_email`. Results should be reported the way Elangovan et al. did: accuracy per similarity bin, where accuracy that climbs with similarity to training means the headline leans on memorisation, and a "clean subset" score shown next to the full score, as the GPT-3 and GPT-4 reports did.

## Synthetic documents must be grounded, gridded and deliberately hard

Document typing is a low-subjectivity, topic-like task, the kind on which LLM-generated data transfers well: on AG News, real data scored 95.3 macro-F1, zero-shot synthetic 89.3 and few-shot synthetic 91.5 ([Li et al. 2023](https://arxiv.org/html/2310.07849v2)). The danger is not subjectivity but sameness. Real data was more diverse than few-shot synthetic, which was more diverse than zero-shot, and **grounding the prompt in real examples recovered about 10 macro-F1 points over zero-shot** ([Li et al. 2023](https://arxiv.org/html/2310.07849v2)). Veselovsky et al. found grounding, discriminator filtering and taxonomy-guided prompting each improved faithfulness ([Veselovsky et al. 2023](https://arxiv.org/pdf/2305.15041)), and Persona Hub shows persona conditioning as a scalable diversity lever ([Ge et al. 2024](https://arxiv.org/html/2406.20094v1)). CheckList-style templates give precise control but produce exactly the narrow, regular text a template-trained model finds easy ([Ribeiro et al. 2020](https://arxiv.org/abs/2005.04118)), so they belong only in targeted functionality tests, never with the training generator's vocabulary.

The practical design is grounded LLM generation conditioned on one cell of an attribute grid per call: line of business, sender persona (wholesaler, MGA underwriter, retail agent, risk manager), source system, market (US or London), length and format, extraction path (native text, OCR'd scan, email body with quoted thread, flattened spreadsheet), and noise level. Length deserves its own axis because the English Laya root reads 512 tokens: a document whose class-defining header falls beyond the window is a realistic hard case. Noise should be applied as a separate seeded post-processing step after labelling, so clean original and noised variant share a label and form a natural invariance pair. Simulated OCR noise recovers much real-OCR robustness ([Xu et al. 2021](https://arxiv.org/abs/2107.07113v1)) but does not replicate real parsers exactly ([arXiv 2608.28595](https://arxiv.org/pdf/2608.28595)). Using at least two generator families, with accuracy reported per generator, turns generator style into a measurable quantity: a large spread means the set measures style, not type ([Maheshwari et al. 2024](https://arxiv.org/abs/2409.11968)).

Hard cases need their own slices. Contrast sets, small expert edits near the decision boundary, cut model accuracy by up to 25% across ten datasets even though the edits were not adversarial ([Gardner et al. 2020](https://arxiv.org/abs/2004.02709v2)); CheckList adds invariance tests, where a label-preserving perturbation must not change the prediction, and directional tests ([Ribeiro et al. 2020](https://arxiv.org/abs/2005.04118)); and aggregate metrics hide poor performance on important subclasses unless those are reported explicitly ([Oakden-Rayner et al. 2020](https://arxiv.org/abs/1909.12475)). Curated hard items must never be pooled into the gated headline, because they move the error level by however many were added. Each contrast edit should link to its parent by `pair_id` and be scored on pair consistency, which is much stricter than accuracy. Anthropic's eval guidance adds irrelevant, missing and overly long inputs and cases humans would disagree on ([Anthropic, develop tests](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests)).

### An intended label is a hypothesis, not ground truth

Li et al. never checked that generated texts matched their target labels, a common gap. Validation needs layers. Rule validators come first: an `acord` row must carry a form number or the form's field layout, a `loss_run` row claim, date-of-loss and paid or reserve fields, an `sov` row location rows with values, and a `broker_email` row email headers or a salutation. Next, a judge from a model family different from both the generator and the fallback classifies the document blind from the guideline, three to five times at non-zero temperature, and must name the cue it relied on so the cue can be confirmed in the text rather than in the prompt. Anthropic recommends grading with a different model from the generator and constraining the grader's output ([Anthropic, develop tests](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests)); GPT-4 showed significant self-preference as a judge, apparently driven by familiarity with low-perplexity text ([Wataoka et al. 2024](https://arxiv.org/abs/2410.21819)); and judges carry position, verbosity and self-enhancement biases ([Zheng et al. 2023](https://proceedings.neurips.cc/paper_files/paper/2023/hash/91f18a1287b398d378ef22505bf41832-Abstract.html)). Two exclusions matter most for this repo. Laya, or any model under evaluation, must never validate labels, because filtering by its agreement leaves only examples it already gets right. And the fallback family (the Ollama Qwen model and whatever runs on Bedrock) must never generate or judge golden rows, or fallback agreement with truth becomes circular.

Diversity should be reported as a small panel of weakly correlated metrics: distinct-n at fixed sample size, Self-BLEU and compression ratio for lexical diversity ([Shaib et al. 2024](https://arxiv.org/html/2403.00553v3)), embedding Remote Clique and Chamfer distance for semantic diversity, grid-cell coverage, and distance to the training snapshot. A two-sample test is a useful extra: if a quick discriminator cannot tell golden rows from training rows, the golden set is a template echo. Until a real anonymised slice exists, golden accuracy should be read as an upper bound on production accuracy.

## Three to five bad labels per class can flip a promotion

Northcutt et al. estimated **at least 3.3% label errors on average across the test sets of ten widely used benchmarks, from 0.15% on MNIST to 10.12% on QuickDraw**, and showed that a smaller model overtakes a larger one once mislabelled test examples rise by only about 5 to 6% ([Northcutt et al. 2021](https://arxiv.org/html/2103.14749)). On the "correctable" subset of ImageNet, ResNet-18 rose from 34th to 1st. Errors concentrate in boundary items, which are exactly where candidate and incumbent disagree, so the distortion of a promotion decision is larger than the raw error rate suggests. Synthetic labels add a correlated failure mode: a generator labels each row by the template it used even when the rendered text is ambiguous, and a model trained on similar synthetic data will agree with those errors.

The guideline must be written, exhaustive and frozen before any agreement study. Krippendorff's requirements, as summarised by Artstein and Poesio, are a clear scheme with step-by-step instructions, stated coder selection and independent coders; adding rules mid-study, relying on collaborators who know the project's intent, or discussing judgements during the reliability exercise "make the resulting data unusable for measuring reproducibility" ([Artstein & Poesio 2008](https://aclanthology.org/J08-4004.pdf)). The reliability sample must cover every category and every complication the guideline addresses. For agreement, Cohen's kappa suits two coders and Krippendorff's alpha more; the convention in computational linguistics treats 0.8 as the floor, 0.67 to 0.8 as tentative, and Artstein and Poesio's own experience is that only values above 0.8 ensured reasonable quality ([Artstein & Poesio 2008](https://aclanthology.org/J08-4004.pdf)). McHugh calls any kappa below 0.60 inadequate ([McHugh 2012](https://pmc.ncbi.nlm.nih.gov/articles/PMC3900052/)). Report a confidence interval, not a significance test, and a full confusion matrix so the overall figure cannot hide disagreement on a small class. At 500 rows, double-labelling everything is affordable and is the clean choice; a Sim and Wright style calculation puts about 165 items as the floor for a kappa interval of ±0.1 ([Bujang & Baharum 2017](https://riviste.unimi.it/index.php/ebph/article/view/29771)).

Adjudication follows measurement, never the reverse. With two humans, majority vote is undefined, so disagreements go to an expert adjudicator, an underwriting operations lead, who records the guideline rule applied. Northcutt's four outcomes make a good adjudication vocabulary: correctable, multi-label, neither and non-agreement ([Northcutt et al. 2021](https://arxiv.org/html/2103.14749)). Items still ambiguous after adjudication are kept with a flag in a separate slice, excluded from gated metrics, and scored on whether the system routes them to fallback with low confidence, which is its intended behaviour; dropping them silently overstates production accuracy, and forcing a label adds noise.

Automated detection is a triage queue, not a correction mechanism. cleanlab's `find_label_issues` ranks suspects from out-of-sample predicted probabilities ([cleanlab filter docs](https://docs.cleanlab.ai/stable/cleanlab/filter.html)), but in Northcutt's study only 51% of confident-learning flags were confirmed by humans, and an estimated 14% of ImageNet errors were missed ([Northcutt et al. 2021](https://arxiv.org/html/2103.14749)). Out-of-sample probabilities for golden rows must come from models trained only on non-golden data (the current Laya checkpoint, or a TF-IDF logistic baseline), never from cross-validation on golden folds, which would breach invariant 4. LLM annotators can beat crowd workers on some tasks ([Gilardi et al. 2023](https://arxiv.org/abs/2303.15056)), but their labels shift with prompt wording and across identical runs ([Reiss 2023](https://arxiv.org/abs/2304.11085)) and their accuracy is "highly contingent" on the dataset and task ([Pangakis et al. 2023](https://arxiv.org/abs/2306.00176)); replacing humans needs a formal comparison against at least three human annotators ([Calderon et al. 2025](https://aclanthology.org/2025.acl-long.782)). Here an LLM is a non-voting column in the agreement table, its run-to-run instability is a useful hardness signal, and the generator label is recorded as one more "annotator" whose agreement with the human consensus measures generator label quality directly.

## Most confusions come from documents that contain or describe another class

Real submission documents are defined by structure more than vocabulary. An SOV is a per-location, often per-building table of construction, occupancy, protection and exposure attributes with insured values by coverage on a stated valuation basis ([Markel SOV form](https://content.markel.com/api/public/content/property-statement-of-values); [Intact SOV form](https://portal.intactinsurance.com/system/files/mydocuments/70048%20%2806-2016%29%20W7777.pdf)); fields include address, construction type, year built, square footage, stories, building and contents values, and fire protection ([Rikor SOV guide](https://rikor.helpjuice.com/en_US/franchise-insurance-101/insurance-101-how-do-i-complete-a-statement-of-values-sov-form)), with ISO construction classes 1 to 6 ([IRMI](https://www.irmi.com/term/insurance-definitions/modified-fire-resistive-construction-iso)) and protection classes that include split values such as 4/4X and 10W ([Verisk PPC](https://www.verisk.com/blog/new-ppc-fire-protection-classes-to-benefit-insurers-communities/)). Real SOVs are messy: merged headers, subtotals mid-table, construction typed as free text such as "JM/frame w mansard" ([CallSphere](https://callsphere.ai/blog/the-loss-run-arrives-as-a-scanned-fax-with-a-handwritten-note-in-the-m.md)) and multi-tab workbooks with inconsistent headers ([Nomad Data](https://www.nomad-data.com/doc-chat/clearing-the-submission-backlog-ai-transformation-for-underwriting-assistants-in-property-homeowners-commercial-auto-and-general-liability-construction-d6c76)).

A loss run is a carrier or TPA printout per policy period, stamped with a valuation date, listing claims with number, date of loss, description, paid, reserve, incurred and status, where paid plus case reserve equals incurred ([CAS](https://www.casact.org/sites/default/files/presentation/clrs_2013_handouts_paper_2482_handout_1315_0.pdf); [Milliman](https://www.milliman.com/ja-JP/insight/A-beginners-guide-to-the-casualty-actuarial-language)). There is no industry-standard format, labels drift ("indemnity paid", "Total Inc."), three to five years is typical, and runs arrive as PDFs, scans, phone photos, spreadsheets or pasted email text ([V7 Labs, loss runs](https://www.v7labs.com/blog/ai-loss-run-analysis-automate-data-extraction)). A no-known-loss letter is the insured's signed certification of no losses for a period ([Admiral](https://admiralins.com/no-known-loss-statement)): loss history in purpose, a letter in form. ACORD 125 is the master commercial application, with 126 (general liability), 130 (workers' comp), 131 (umbrella) and 140 (property) attaching to it ([Semsee](https://semsee.com/blog/acord-125)); 125 itself contains a prior carrier and loss history section. ACORD 139 is a Statement of Values ([Instafill](https://instafill.ai/category/acord-forms)), and certificates (ACORD 24, 25, 27, 28) are post-bind proof-of-coverage documents issued "as a matter of information only" ([ACORD certificates FAQ](https://acord.org/docs/default-source/forms/acordcertificatesfaq)). The broker cover email is a narrative wrapper around attachments in mixed formats, and its body can itself carry key data ([V7 Labs, triage](https://www.v7labs.com/blog/ai-insurance-submission-triage-processing)); underwriters reward summaries with specific facts ([Insurance Thought Leadership](https://www.insurancethoughtleadership.com/how-to-catch-the-underwriters-attention)). `other` is wide: supplemental applications, financials, appraisals that carry SOV attributes, quotes, binders, London Market MRC slips with their six sections ([Buckhill](https://cdn.buckhill.co.uk/help/article/key-concepts)), presentations, invoices and KYC material. The homonym trap is real: a construction "schedule of values" is a pay-application budget, not an insurance SOV ([Archdesk](https://archdesk.com/blog/schedule-of-values-template-construction)).

No public dataset or peer-reviewed benchmark exists for this task; vendor taxonomies converge on ACORD, SOV, loss run, email and a remainder ([V7 Labs](https://www.v7labs.com/blog/ai-insurance-submission-triage-processing); [Intellect AI](https://www.intellectai.com/magic-submission/)), which matches `CRITERIA` in `domain.py`. Note that the `broker_email` description scores the cues "from, re, fwd, attached, regards", which is exactly the vocabulary that contrast pairs must break. The edge cases below need a written rule before labelling starts. Rules marked "decide" are taxonomy choices for the team; the recommendation is given, and either way the rule must be frozen into guideline v1.0 and the `CRITERIA` text aligned with it.

## Golden-v2 build specification

The specification below reconciles the notes' competing proposals (a 70/20/10 in-distribution, contrast and invariance split; a 30/50/20 in-template, out-of-template and out-of-generator split; and 150 rows for `other`) into one buildable set. It keeps invariant 3 intact: every golden row is template-disjoint from training, so in-template generalisation is measured by grouped cross-validation on training data rather than by relaxing the exclusion for a golden slice.

### Slice composition: a 360-row gated core and 140 reported challenge rows

| Slice | Rows | sov | loss_run | acord | broker_email | other | Purpose and use |
|---|---|---|---|---|---|---|---|
| `core` | 360 | 70 | 70 | 65 | 70 | 85 | Representative, varied over the attribute grid; drives all gated metrics |
| `boundary` | 64 | by rule | | | | | Edge cases 1 to 17, about 4 rows each; regression warnings per rule |
| `contrast` | 40 | by edit | | | | | Minimal edits of core parents that flip the label; pair consistency |
| `invariance` | 36 | follows parent | | | | | Noise variants of core parents: OCR substitutions, truncation past 512 tokens, forwarded wrappers, UK date and currency formats, dropped headers |
| Total | 500 | | | | | | |

Within `core`, about 45% of rows come from generator family A, 35% from family B and 20% from hand-written or hand-perturbed real-derived documents; neither family may be the training generator's model or the fallback model, and the judge must be a third family. Each class in `core` spans at least 20 distinct composite groups, with no more than 5 rows per group, using the keys from the leakage section (SOV: broker plus header signature; loss run: carrier system; ACORD: form number plus edition; email: broker firm; other: source or near-duplicate cluster), each prefixed with generator identity. `acord` gets the fewest rows because it is expected to be the easiest class; `other` gets the most because it is the most heterogeneous and most likely to have recall near 0.85, where 85 rows give roughly ±0.07. Generate about 15% more candidates than needed (around 575) to absorb rejects. Two companions sit outside the 500: a `real` slice of anonymised broker documents reported separately as it grows, and, if budget allows, a sequestered 100 rows scored only at release to detect overfitting from repeated use of `core`. Ambiguous rows that survive adjudication live in `boundary` with an `ambiguous` flag and are scored only on routing behaviour.

| Field | Content |
|---|---|
| `doc_id`, `content_hash`, `golden_version` | Identity; hash uses the same normalisation as `doc_hash` |
| `text`, `token_count` | Serialised document as Laya will see it, plus length against the 512 window |

### Generation and validation steps

| Step | Action | Exit criterion |
|---|---|---|
| 1 | Write guideline v1.0: class definitions, the 18 rules above, two clear positives per class and a worked example per rule; align `CRITERIA` | Signed off by underwriting operations |
| 2 | Build golden-only generators, prompts, lexicons and slot lists in a separate module; seed with anonymised real examples where available | No shared code or slot list with `scripts/` |
| 3 | Generate about 575 candidates, one grid cell per call; derive contrast and invariance rows from core parents | Grid coverage at least one row per populated cell |
| 4 | Run rule validators and the blind third-family judge (3 to 5 runs, cue named) | Failures go to human review, not the bin |
| 5 | Pilot 50 rows with two annotators, revise guideline, discard pilot agreement | Guideline frozen |
| 6 | Double-label all rows independently, blind to generator label, judge and model output | Alpha at least 0.80 overall with bootstrap CI; per-class one-vs-rest kappa at least 0.70, otherwise revise guideline and re-label the class |
| 7 | Adjudicate every disagreement, including human versus generator | Every row has an outcome and, if changed, a cited rule |
| 8 | Triage: cleanlab on non-golden-trained probabilities, Laya-and-LLM-agree-against-label, LLM instability across runs | Every flag gets a human decision; nothing relabelled automatically |
| 9 | Run diversity panel and two-sample discriminator against the training snapshot | Discriminator well above chance; metrics recorded in datasheet |
| 10 | Run the contamination report, select to final counts, freeze with manifest, metric-code hash and datasheet | Zero hard-fail leaks |

### Leakage checks wired into every snapshot build

The contamination report runs as a service behind a port, on golden-v2 at freeze and on every training snapshot thereafter, writing per-row results to `var/runs/<ts>/`. Hard failures, which block the snapshot and any promotion trained on it, are an exact match on normalised text; any shared composite group key or near-duplicate component; a verbatim span (any of three 50-character substrings, or a shared 8-word n-gram); character 5-gram similarity of 0.8 or more; and any shared rare slot value (insured name, address, policy number). The band from 0.5 to 0.8, and embedding similarity above a cut-off calibrated on same-template versus independent same-class pairs, goes to a review list. The report also records accuracy per similarity bin and the clean-subset score beside the full score.

### Promotion gate changes

| Current rule | Replacement | Reason |
|---|---|---|
| Block if candidate accuracy < incumbent (any drop) | Block if the `core` prior-weighted accuracy drops by more than 0.01, or if one-sided mid-p McNemar shows the candidate worse at p < 0.05 | One item is 0.2 points; test the evidence, not the noise |
| Block if any class recall drops by more than 0.05 | Block if a class drops by more than 0.05 and its one-sided mid-p McNemar is below 0.10, or drops by more than 0.10 outright; log b and c per class | Lenient p chosen deliberately because a false block is cheaper than a false promotion |
| Block if ECE rises by more than 0.02 (10 equal-width bins) | Block if the lower bound of the 95% paired bootstrap interval on Brier difference is above 0; report debiased ECE with its bootstrap interval and gate on its lower bound exceeding 0.02; freeze the estimator | Binned ECE at n = 500 is dominated by bias and noise |
| None | Same per-class rule on the generator-B subset of `core` and, once it has 30 or more rows per class, on `real` | A candidate must not buy generator-A gains with generalisation losses |
| None | Warn on any regression of `boundary` rule groups, `contrast` pair consistency or `invariance` stability, using McNemar on the slice | Known failure modes are checked, not averaged in |
| None | Refuse comparison unless both reports share golden version and metric-code hash; refuse any candidate whose snapshot failed the contamination report | Comparisons on the same exam only |

Every report should show macro, prior-weighted and per-class figures with Wilson intervals and counts, coverage and selective risk at matched coverage, and the gap between generator families.

## Conclusion

The research reframes what "accurate" means for this golden set. Five hundred synthetic rows cannot pin down absolute accuracy to better than a few points, and no amount of care will make them match production until real anonymised documents arrive; what they can do, if built independently and labelled under frozen rules, is make reliable paired decisions between two checkpoints. That shifts effort away from chasing more rows and towards the three things that silently corrupt those decisions: a shared generator, a handful of wrong boundary labels and a gate tuned to noise. Each has a cheap structural fix, and none requires more data.

The less obvious implication is that the labelling guideline is a product decision, not an annotation chore. Whether a certificate is `acord`, whether a no-known-loss letter is a loss run, and when an email with a pasted table stops being an email all determine which extractor fires downstream, and the golden set will encode whatever answer is written down. Writing those rules first, aligning `CRITERIA` with them and testing them through the boundary slice turns the golden set from a scoreboard into the specification of what the typer is meant to do. Where the evidence is thin (no published measurement of same-generator inflation, no sourced threshold for embedding near-duplicates on short insurance text, no measured production prior), the build should measure it itself through the cross-generator gap, calibrated similarity distributions and decision-log volumes, and record the results in the golden-v2 datasheet.
